對話範疇防護：讓小羽只做它該做的事

我們賣的是「陪你梳理關係卡點」，不是通用 AI 助理。如果使用者能拿它寫作業、問程式、問股票，那小羽的角色就模糊了——不只偏離產品定位，一個定位在心理陪伴的產品，被期待要有清楚的邊界，這也是使用者信任感的一部分。這份文件把「業界實際怎麼做這件事」攤開，再給一個可以動工的方案。

01

核心決策：怎麼判斷「這是不是關係相關的問題」

三種做法，複雜度跟準確度是取捨關係。

方案 A

只靠 system prompt 約束（現況）
  • 不用改架構，一段文字就能上
  • 使用者換個問法就能繞過（「假裝你是工程師…」）
  • 沒有紀錄、無法追蹤攔了多少次、攔對了沒
選這個會怎樣：等於現在的狀態，你會一直看到使用者反應「它什麼都回」，因為 prompt 約束本來就擋不住刻意繞過。
建議採用

方案 B

輕量分類 Step（先判斷、再決定要不要正常回答）
  • 每則訊息先過一次 gpt-4o-mini 分類，便宜（比正式回應輕很多）
  • 輸出是機率分數 p ∈ [0,1]，用門檻值切成兩類：relevant / off_topic
  • 攔下的訊息會記錄，後台看得到、能微調規則
  • 多一次 API 呼叫，回應會多 200-400ms 延遲
選這個會怎樣：大多數中小型 AI 產品實際採用的做法——不用裝重框架，一週內可以做完，且能持續看數據調整「多嚴/多鬆」。

方案 C

導入完整防護框架（NeMo Guardrails 等）
  • 功能最完整，未來要加更多規則（安全風險偵測等）都有現成機制
  • 要學一套新的設定語法、多一層維運成本
  • 對現在的規模是殺雞用牛刀
選這個會怎樣：值得先記在待辦，等產品規模變大、規則變多（不只範疇，還要防詐騙誘導等）時再升級過去，現在做投報率低。
02

判斷範例——二元分類，拿不準就當相關

改成兩類：相關／離題。拿不準的中間地帶，不另外反問使用者，直接當「相關」正常認真回答——不製造「被盤問」的體感，也不會把正常但講法特殊的關係問題卡住。這個做法對應新加坡 GovTech 團隊發表的 離題提示偵測論文（ICLR 2025）——論文裡的分類器本來就是標準二元分類，輸出一個機率分數，由門檻值決定要不要攔，不是三分類。

使用者訊息判斷小羽的處理方式
「我男朋友已經三天不讀不回了」 relevant 正常走原本的諮詢對話流程
「我覺得我最近工作壓力很大」 relevant 拿不準是不是「職場人際卡點」，一律當相關、認真回答，不反問、不卡使用者
「幫我寫一篇 500 字的企業倫理報告」 off_topic 不回答內容，委婉說明角色定位，引導回關係相關的話題
「幫我算一下 87 乘以 34」 off_topic 不回答，說明這不是它能協助的範圍
03

資料流程

分類這一步插在「使用者送出訊息」跟「正式產生回覆」中間，多一個路口，不動原本的對話邏輯。

邏輯方向已經定了（方案 B），這幾個細節會影響使用者的實際體感，你來拍板。

攔下離題訊息時，怎麼回應使用者？

委婉引導
（建議）
不直接說「我不能回答」，改成「這裡比較適合聊關係方面的事，你今天有沒有什麼想聊的？」——保持陪伴的語氣，不製造被拒絕的感覺。
明確說明
範圍
直接告知「我只能協助關係諮詢相關的問題」。更清楚但比較生硬，適合如果你們發現使用者一直搞不懂它的定位。

門檻值要設多嚴？

分類器輸出的 p 是「離題機率」：p 超過門檻值才判 off_topic。

寬鬆
（建議）
門檻設高一點（例如 0.6），只有機率分數明顯偏向離題才攔，拿不準的一律當 relevant 讓它正常回答。誤攔風險低，使用者體感好。
嚴格
門檻拉低（例如 0.4），更容易把模糊訊息判成離題。攔得乾淨，但容易誤攔真的在講關係卡點、只是講法比較跳的使用者。GovTech 論文內部實際部署用的區間是 0.4–0.6，可以從這個範圍挑一個起步，再用後台數據滾動調整。

範疇防護記錄要不要存訊息原文？

存原文
後台微調規則時最好用，能直接看到判斷錯在哪。但這是使用者的對話內容，存起來要考慮隱私揭露範圍、留存期限。
只存分類結果
不留原文，只記「這則被判什麼、幾點」。隱私風險最低，但後台没辦法回頭檢討具體判斷是否合理，微調規則會比較憑感覺。

本文件為功能提案、非最終規格。核心決策（方案 B：輕量分類 Step、二元分類 + 機率門檻，拿不準一律算相關）已依需求推導； 三項待決策（回應語氣、門檻值、記錄是否存原文）確認後才會往下拆 migration 與開發任務。
