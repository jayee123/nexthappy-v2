## 3. ⭐⭐⭐ 重大產出：3 個 D10 級別的 insight

### 3.1 找正向證據成功（避免「她從來都不 ___」劇本陷阱）

> 「我跟她聊到她感興趣的話題時，例如：『我發現附近一家新開的餐廳有她可能有興趣吃的東西』，跟她分享時，**她眼睛亮了，聲音也提高了，驚訝了，也講了她的想法**。」

→ ✅ **「被在乎」不是無望的狀態**。對比餐廳例 vs AI app 例，差異不在「她在不在乎我」，而在**話題對她的相關度**。
→ Steve 自發完成 protocol §3.6.2 設計目的：把僵化的「她從來都不在乎我」劇本拆解成「**有時候有、有時候沒有**」可變狀態。

### 3.2 「我卻不在乎」自發拐彎（D10 核心 insight）

> 「她曾跟我反應過，我還是改不了。我這樣一回想，**忽然記起來了她曾跟我反應，我卻不在乎**。」

→ Steve 在描述「她不在乎我的想法」的反例時，**自發翻轉鏡頭**：意識到她也曾跟他反應「你講太長我覺得累」，而他沒接住。
→ 這個「我卻不在乎」是**完全 Steve 自己挖出來的**——不是 AI 引導、不是 AI 分析她——是學員自己在 W2.想 內觀過程中浮上來的鏡像。

### 3.3 ⭐⭐⭐ 「鏡子法則」自發覺悟（從 D1-D10 累積中長出）

> 「我們從 Day1 到 Day10 的『刻意練習』讓我明白清楚了，
> 我因為（前因）沒有滿足她的需求，重視她的感受（或沒有接住），日積月累因我的行為導致如今這個結果：
> 她也就不會滿足我的需求，重視我的感受。
> **我怎麼對人，別人也就會怎麼對我，像鏡子一樣反射到我自己身上。**
> 我要改善我們之間的情況，得從改變自己本身的行為開始做起。」

→ 這是 spec §1.6「**一次真正的頓悟，勝過一百次理論灌輸**」+「製造頓悟」設計目標的**頂級實現範本**。
→ 不是 AI 教給他的——是 D1–D10 觀感想行積累後**從學員內部長出來的因果線**。
→ 直接對應 spec §4.10 D17 修復公式（W1.觀 + W1.行 + W2.行 三維度組合）的種子已埋下。

### 3.4 「我心疼她」自發 empathy 出現（W2.感 + W2.想 整合時刻）

被問「如果你只說一遍『我想被她在乎，但我也沒在在乎她』——身體裡有什麼感覺？」時，Steve 回：

> 「我感覺到她不被我在乎，重視，她有強烈的失落感，不被重視的感覺，她也想要被重視，被在乎，被理解，**我心疼她**。」

→ 這四個字本身是**新出現的真感受**（W2.感(己)）。
→ 「我心疼她」內含的「想」：**Steve 不只想被她在乎；Steve 也想能在乎她**。需求是雙向的。
→ ⚠️ **這段話技術上違反 §1.12.3 hard rule「替對方代言需求」**（「她也想要被重視、被在乎、被理解」推測對方需求）——但這是 Steve **自發的**同理共鳴，不是 AI 引導的對方分析。

→ **這直接催生了 spec v1.0.3 §1.12 例外條款 v2**（見下面 §5 friction note）。

## 5. ⭐⭐⭐ Friction Watchlist → spec v1.0.3 patch material

### 5.1 §1.12 W2 內觀紀律 需要「例外條款 v2」（最重要）

**問題**：
- §1.12.3 hard rule 寫「替對方代言需求」是禁區
- §1.12.4 redirect 範本是「先停一下分析她，回到你身上」
- 但 Steve「我心疼她，她也想要被重視」是學員**自發**的同理共鳴
- 如果 AI 嚴格守紀律 redirect、打斷 Steve、強迫他回去拆自己——**會錯失 D10 最珍貴的 W2.感 + W2.想 整合時刻**

**核心區分**：

| 來源 | 是否違反 §1.12 | 例子 |
|---|---|---|
| **AI 主動引導**對方分析（INTJ 模式 / MBTI 解讀）| ❌ 違反 §1.12.3 hard rule | D9 production app 的 70% 篇幅問題 |
| **學員自發**的同理共鳴 | ✅ **不違反**——是內觀的成熟果實 | Steve「我心疼她」、「她也想要被在乎」|

**建議 v1.0.3 patch**（已建 task #29）：
- §1.12.8 例外條款 → 拆成 §1.12.8a（W3 重整合允許重新引入對方視角）+ **§1.12.8b（自發同理共鳴）**
- §1.12.4 redirect 範本 → 加 ✅ **不 redirect 的條件**：「當學員自發出現『我心疼 ___』『___ 也想 ___』這類同理句式時，AI 不應 redirect，應該收下、確認、繼續往下深化」
- 區分原則：**主動權誰啟動的**——AI 啟動 = 禁區；學員啟動 = 珍貴

### 5.2 §4.8 D10 設計可選擴充：「雙向 insight」hint

D10 self-test 自然產出「鏡子法則」覺悟——這是**設計意圖內的副產品**。spec §4.8 可以考慮加一段：

> 「§4.8.x 雙向覺察提示：D10 W2.想 自發雙向 insight 的可能性
> 部分學員會在 D10 釐清需求後自發意識到『我也沒在在乎她』——這是 D17 修復公式的天然種子。
> AI 不應主動引導這個方向，但學員自發提出時應當作 D10 級 insight 收下。」

（可選，不必強推；但 spec 留個 hint 提醒未來 prompt 工程時要 hold 住此類 organic insight）

### 5.3 protocol §3.6.3 reframe（已隱性處理）

protocol 原問：
> 「如果太太看到『我需要的是 X』（不是『你要做 Y』），**她的反應**會不會不一樣？」

→ 嚴格按 §1.12.3 此題違反「推測對方反應」。本場我**自行 reframe** 為：
> 「如果你只說一遍給自己聽——『我想被她在乎，但我也沒在在乎她』——**你身體裡**有什麼感覺？」

→ 把焦點從「她的反應」拉回「你的身體感覺」。
→ 結果：Steve 當場給出「我心疼她」+「鏡子法則」雙重產出。

**建議**：protocol §3.6.3 應該重寫成「你自己身體感覺」版本，保持純 W2 內觀。

### 5.5 ⚠️ §4.9.4 洗碗主錨例 容易被學員誤讀為「練習題」（D10 後反思補充）

**發現脈絡**：
D10 self-test 收尾後 Steve 反問：「為什麼會出現『洗碗主錨例』？我跟小玫沒有洗碗的困擾呀。」

**問題本質**：
spec §4.9.4 把洗碗例設為 W2 主錨例（demo 4 步如何串起整段）—— 但 spec **沒有明示「主錨例 = 公式 demo，不是練習題」**。學員（包含 Steve）容易誤讀為「我得用洗碗情境來練」。

**洗碗例的潛在共鳴問題**：

| 對誰共鳴度高 | 對誰共鳴度低 |
|---|---|
| 異性戀 + 同居 + 太太抱怨型 | 男學員（容易 misread 為「家事溝通課」）|
| 中年家庭關係 | 未婚 / 同性 / 不住一起 / 沒小孩 |
| 真的有家事分工困擾的 | 困擾在「不被看見 / 被冷淡 / 期待落差」型 |

→ Steve 的真實困擾是「**分享 AI app 想法被冷淡**」，跟洗碗 0 相關。如果 D11 沒清楚分層，Steve 會卡在「這例子跟我不像，怎麼套？」。

**建議 v1.0.4 patch**：
1. **§4.9.4 加「使用守則」前言段**：
   > ⚠️ 洗碗例 = **公式 demo**，不是練習題。學員自己的真實情境可能完全不同（吵架 / 冷戰 / 不被看見 / 期待落差 / 滑手機 / 加班 / 孩子議題⋯）—— **4 步骨架同樣適用**。AI Tutor 在 D11 morning content 必須**主動說明**這層分層，避免學員誤以為要練洗碗。
2. **§4.9.4 候補 / 補充例**：可選——加 1-2 個非家事類的 4 步主錨例（如「分享想法被冷淡」「期待落差」），讓不同情境學員都有共鳴錨。
3. **AI Tutor system prompt（W2.行 day）**：加一條 hard rule——「介紹完洗碗例後，**主動問**學員：『你自己最近一次想表達需求但沒講好的場景是什麼？』再用學員真實情境練 4 步」。

**為什麼這條重要**：
- §1.6 信念說「**用自己想要的方式去愛對方** = 猴子給貓香蕉」—— 如果 spec 自己只用一種主錨例（洗碗）就把所有學員當「同一種貓」對待，**等於 spec 自己違反了 §1.6**。
- 真實情境 → 真實練習 → 真實肌肉記憶。用不共鳴的例子練，肌肉記憶不會建立。

→ 這是 v1.0.3 → v1.0.4 patch material（待 D11 chat run 跑完後一起 patch，避免 spec 過度頻繁變動）。

## 8. 結論

**D10 self-test 最大產出 = 3 件事**：

1. **學員端**：Steve 親自跑出「鏡子法則」+「我心疼她」雙向覺悟——D10 設計意圖（從感受挖到內在需求）100% 達成 + 自發整合超越設計目標
